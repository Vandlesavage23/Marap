# Screen specs (Bible §5.5)

One file per feature: purpose, routes, API calls, the explicit UI states, and which test covers each state.
States are the Bible's six: **loading**, **data**, **empty**, **error** (retryable), **restricted** (reason), **offline**.

Test column conventions (paths are under `apps/mobile/`):

* **unit/widget** = `test/...` (run by `flutter test`, uses fakes).
* **contract** = `test/contract/...` (real Django server; `tool/run_contract_tests.sh`; verifies the *server answers* a state depends on, not the pixels).
* **integration** = `integration_test/...` (device/emulator; compiles under `flutter analyze` once `integration_test` is a dev dependency; not run in CI).
* **GAP** = no test asserts this state. These are listed per file and again below.

Status: generated by reading the test names on the date of writing, not by running a coverage tool. Re-check when tests move.

## Known cross-cutting gaps

* **Goldens**: only the shared kit has golden tests (`test/core/kit`); no feature screen has a golden, so visual regressions per state are unchecked (Bible §13.1 asks for goldens for every screen state).
* **Dark theme**: only the profile builder has a dark-theme render test (`profile_screens_test.dart: dark theme renders the builder`).
* **Large text / small screen**: only the kit is tested at 200% text (`kit_a11y_test.dart`); no screen is.
* **Real vendors/devices** (camera, mic, store purchase, FCM, FLAG_SECURE) are behind fakes; see `docs/STATUS.md`.
